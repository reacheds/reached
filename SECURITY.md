# Security Policy

The Reached project team takes security issues seriously and welcomes reporting of vulnerabilities from community members, researchers, and users.

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1   | :x:                |

## Reporting a Vulnerability

**Please DO NOT open a public GitHub Issue for security vulnerabilities.**

To report a vulnerability:
1. **GitHub Private Vulnerability Reporting:** Navigate to the **Security** tab of this repository and click **"Report a vulnerability"** to submit a draft security advisory.
2. **Email:** Alternatively, contact the maintainers directly at **security@reached.org**.

### What to Include in Your Report
* Description of the vulnerability and its potential impact.
* Step-by-step instructions or Proof of Concept (PoC) to reproduce the vulnerability.
* The affected component(s) (`apps/bot`, `apps/web`, `packages/database`, etc.).
* Any proposed patches or mitigations.

### Response Timeline
* **Initial response:** Within 48 hours acknowledging receipt of your report.
* **Assessment & Triage:** Within 5 business days detailing next steps and estimated remediation date.
* **Coordinated Disclosure:** We kindly request that you give us adequate time to fix the vulnerability before disclosing it publicly.
